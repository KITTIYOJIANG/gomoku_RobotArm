# STM32 / 实机协议说明

本文件严格区分“用户给定且已实机确认的运行协议”和“工作区内可复制的 Stage-1 参考固件”。本次整合未编译、修改或烧录固件。

## 实机运行协议（V0.1 权威约定）

- Windows 端口默认：`COM6`（GUI 可下拉选择）。
- 波特率：`115200`，ASCII，无自动连接。
- 多舵机同步目标：`{#000P1500T1000!#001P1500T1000!...}`。
- 单舵机目标：`#005P1500T0500!`。
- 同一对花括号中的目标按同步动作理解；字符串内 ID 顺序不是实际运动先后顺序。
- 需要先后的动作必须发送多条命令，并由上位机 ArmSequenceWorker 依次等待。
- 急停：`$DST!`。
- 气泵关闭/释放：`#005P1500T0500!`。
- 气泵吸取并保持：动作中的 `#005P2500Txxxx!`。
- 006、007 在 V0.1 所有固定姿态中保持 1500。

## 参考固件能力

复制来源：`gomoku_arm_controller/firmware/jibot1_stage1`。

- 芯片：STM32F103C8。
- 主机命令口：USART1，115200。
- 舵机总线：USART3，115200。
- `src/z_usart.c` 的旧协议接收器可按 `$...!`、`#...!`、`{...}` 和 `<...>` 分类收包。
- `src/z_action.c` 的旧路径包含单/多舵机解析、W25Q64 动作组和 `$DST!`。
- PB5 蜂鸣器驱动位于 `src/z_gpio.c`。
- 旧路径存在 `#nnnPRAD!` 位置读取能力和 `@GroupDone!` 动作组完成文本。

## 关键冲突：SAFE_STAGE1

当前参考工程的 Makefile 和 Keil 配置启用了 `SAFE_STAGE1`。该编译路径由 `USER/safe_main.c`、`safe_console.c`、`arm_safety.c` 和 `servo_bus.c` 组成：

- 接受换行结束的 `status`、`beep,n`、`test_joint,nnn`、`stop`、`$DST!`、`rescan`、`home` 等安全命令。
- `$DST!`/`stop` 会广播 `#255PDST!`。
- 明确不转发原始多舵机 PWM。
- ID 005 在 Stage-1 guard 中为只读，不允许作为气泵动作通道。
- `observe`、`pick_ready`、`park` 仅为未实现接口。

因此，这份参考工程不能证明当前实机能执行 V0.1 原始 PWM，也不能直接重新编译后替换当前实机固件。实机测试前必须由操作者确认 COM6 所连控制器仍运行兼容原始 PWM 的既有固件。

## 回传与等待策略

- 原始固定 PWM 协议没有在当前资料中给出可靠的逐条到位 ACK。
- Stage-1 的位置读取和 `OK TEST_DONE` 属于另一安全调试协议，V0.1 上位机不得混用。
- 当前上位机策略：每条姿态命令等待命令中最大 `T` 加 `action_wait_margin_ms`（默认 200 ms）；吸取与释放再分别等待 700 ms。
- 这种时间策略不是到位反馈。负载、电源、舵机故障或碰撞均可能使实际运动与等待时间不一致。

## 蜂鸣器

参考 Stage-1 协议支持 `beep,1` 至 `beep,5`，但它不属于已确认的实机原始 PWM 接口。V0.1 GUI 的“蜂鸣器测试”保持禁用，避免伪造兼容性。
